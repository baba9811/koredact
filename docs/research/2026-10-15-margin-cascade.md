# 마진 게이트 캐스케이드

요구사항: 공개 fp32 모델의 사후 양자화본으로 추론 속도 확보, 마스킹은 fp32와 동일하게 유지. 기본값·기존 동작 유지,
호출자의 명시적 opt-in만 허용. 이전 측정(제공 수치, `test` 분할 1,590행, koredact 창 1,852개(400/100자), 토큰 200,309개):

- 블록 단위 W8A8(MatMulNBits 8비트, 블록 32, `accuracy_level` 4): 토큰 argmax 7개(창 6개) 변경, 이름 1건의 1글자 노출.
- 동적 INT8: 토큰 argmax 26개(창 15개) 변경.
- 변경 토큰은 모두 양자화 모델의 확신이 낮은 위치. 변경 토큰의 양자화 top-1·top-2 로짓 차 최댓값 0.19(W8A8), 1.05(동적 INT8).
- 1 CPU Linux arm64 컨테이너의 400자 창 1개: fp32 392 ms, 동적 INT8 134 ms, W8A8 177 ms.

## 공식 근거와 적용

- [Park et al., Big/Little Deep Neural Network for Ultra Low Power Inference, CODES+ISSS 2015, pp. 124-132](https://doi.org/10.1109/CODESISSS.2015.7331375):
  작은 망 먼저 실행, 결과의 확신이 낮을 때만 큰 망 실행. 확신 척도는 상위 두 출력 점수 차(score margin).
  적용: 빠른 양자화 모델 먼저 실행, 창 안 비특수 토큰의 top-1·top-2 차 최솟값이 `margin` 미만인 창만 fp32 재실행.
  차이: softmax 점수 대신 로짓 차 사용. 아래 인증 조건이 로짓 오차 기준이기 때문.
- [Wang et al., IDK Cascades: Fast Deep Learning by Learning not to Overthink, UAI 2018, PMLR R16:579-589](https://proceedings.mlr.press/r16/wang18c.html)
  ([arXiv:1706.00885](https://arxiv.org/abs/1706.00885)): 재학습 없이 사전 학습 모델을 캐스케이드로 조합, 판단 보류
  ("I don't know") 입력만 비싼 모델로 전달. 적용: 공개 fp32 모델과 그 양자화본을 재학습 없이 조합. 판단 보류 규칙은
  학습 대신 측정 기반 고정 마진.
- [ONNX Runtime 양자화](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html):
  "Quantization is not a loss-less transformation." 동적 양자화는 활성값 scale·zero point를 실행마다 계산.
  [MatMulNBits](https://github.com/microsoft/onnxruntime/blob/main/docs/ContribOperators.md): 가중치를 K축 블록 단위로
  양자화, `accuracy_level` 4는 입력 A의 내부 int8 양자화 허용. 적용: 런타임이 양자화본의 fp32 동일성을 보장하지 않으므로
  마진 기반 재실행으로 보정.

인증 조건: 한 토큰에서 모든 클래스 j에 대해 양자화 로짓 q와 fp32 로짓 f의 차가 |q_j - f_j| <= ε이고 양자화 argmax c의
마진이 q_c - q_j >= τ > 2ε(모든 j != c)이면 f_c - f_j >= (q_c - ε) - (q_j + ε) >= τ - 2ε > 0, 즉 fp32 argmax도 c.
스팬의 위치·유형은 argmax 라벨과 오프셋만으로 결정(그룹화·창 병합·디코더가 점수 미사용). 모든 창이 조건을 만족하거나
fp32로 재실행되면 `predict` 스팬의 (start, end, type)은 fp32와 동일.

- 측정 ε(전 토큰·전 클래스 최대 절대 로짓 차, 제공 수치): W8A8 1.23, 동적 INT8 1.84. 필요 τ: 2.46 초과, 3.69 초과.
- 재실행 창 비율(제공 수치): W8A8 τ 2.5에서 9.0%, 동적 INT8 τ 4.0에서 14.2%.
- 예상 속도(위 창 1개 시간 기준): W8A8 177 + 0.090 × 392 = 212 ms(fp32 대비 1.85배),
  동적 INT8 134 + 0.142 × 392 = 190 ms(2.07배). 재실행 비율은 창 수 기준, 창 길이 차이 미반영.
- 한계
  - ε는 이 데이터의 측정값, 미관측 입력의 상한 아님. τ에 여유 필요. 입력 분포가 바뀌면 ε·재실행 비율 재측정 필요.
  - 재실행하지 않은 창의 점수는 양자화 모델 값. 렌더링의 겹침 해소가 점수를 쓰므로 유형이 다른 스팬이 겹친 구간의
    치환 유형 선택은 달라질 수 있음. 가려지는 문자 범위는 동일.
  - 두 모델 동시 적재로 메모리 증가. 배치 워커마다 두 세션.

## 구현과 검증 범위

- 공개 계약: Rust `Masker::with_fallback(dir, margin)`·`fallback_stats()`. Python `Masker(..., fallback_dir=, fallback_margin=)`,
  `Masker.from_pretrained(..., fallback_repo=, fallback_revision=, fallback_margin=)`, `fallback_stats()`. 기본값 없음,
  `DEFAULT_REPO` 유지.
- 모듈 위치: 판정은 `model/cascade.rs`(창 로짓 선택·카운터), 조합은 `lib.rs` 파사드(대체 번들 검사·적재·추가 세션 복제).
- 판정: 창마다 빠른 모델 실행 후 비특수 토큰의 top-1·top-2 로짓 차 최솟값이 τ 미만이면 같은 인코딩으로 정밀 모델 실행,
  그 창 전체(argmax·softmax 점수·이후 단계)에 정밀 모델 로짓 사용. τ와 같으면 빠른 모델 유지. 동점은 차 0으로 재실행.
  라벨 1개 또는 비특수 토큰 없는 창은 재실행 없음.
- 대체 번들 검사: 라벨 맵(파싱 결과)과 `tokenizer.json`·`tokenizer_config.json` 바이트 비교. `onnx/model.onnx`와 라벨 외
  `config.json` 필드만 차이 허용, 불일치 시 생성 오류. τ는 0 초과 유한값만 허용.
- 정밀 모델 세션: 같은 `threads`·장치 선호, 가속기 실패 시 같은 CPU 재시도 규칙.
- 배치 워커: 추가 세션도 같은 기본 번들·`threads`·장치 선호·대체 번들·τ로 적재, 카운터는 공유 원자값. `with_fallback`
  호출 시 기존 추가 세션 폐기, 다음 배치 호출에서 대체 모델과 함께 재적재.
- 카운터: `fallback_stats()` = (처리 창 수, 재실행 창 수). 대체 모델 지정 이후 누적, 기본·추가 세션 합산. 대체 모델 없으면
  (0, 0). 재실행 시도 후 정밀 모델 실행 성공 시에만 재실행 수 증가.
- 범위 제외: 기본 대체 모델·기본 τ, τ 자동 보정, 정밀 모델 세션의 장치 정보 노출, 토큰 단위 부분 재실행, 세션 간 가중치
  공유, 양자화 모델 생성·배포, 버전 변경(릴리스 시 별도 결정, 공개 API 추가로 minor).

## 로컬 검증 결과

- Rust: `cargo test --release --no-default-features --features load-dynamic`에서 단위 29개·디코더 벡터 1개 통과. 신규 5개는
  ORT 불필요(마진 판정 4개: 특수 토큰 제외·동점·τ 경계·τ 검증, 대체 번들 검사 1개). ORT 필요 검사 5개
  (`--lib -- --ignored`, ONNX Runtime 1.29.0 동적 라이브러리) 통과, 신규 2개:
  - 정밀 모델 적용: 소형 번들의 `classifier.bias` B-NAME 항목을 50으로 바꾼 사본을 대체 모델로 지정. τ = `f32::MAX`
    (모든 창 재실행)에서 `predict_raw`·`predict` 결과가 대체 모델 단독 실행과 점수까지 동일, 기본 모델 출력과는 다름.
    같은 번들을 대체 모델로 지정하면 τ 4종 모두 기본 출력 유지. 처리 창 수는 창 분할 수와 일치.
  - 추가 세션: 대체 모델 없는 추가 세션 적재 후 `with_fallback` 호출 시 기존 추가 세션 폐기. `workers` 3, 2 배치 결과가
    순차 결과·대체 모델 출력과 동일, 추가 세션 2개 모두 같은 대체 번들·τ 보유. 카운터는 순차 1회분의 정확히 3배.
  - 변이 검사: τ 경계 `<`를 `<=`로, 특수 토큰 제외 제거, 정밀 로짓 폐기, 추가 세션의 대체 모델 누락, 추가 세션 카운터
    비공유, 기존 추가 세션 유지, 라벨 맵 검사 생략. 7개 변형 모두 검사 실패 확인.
- Python: 로컬 빌드 휠로 smoke·`runtime_options.py` 통과(ONNX Runtime 1.29.0). 같은 번들 대체 시 `predict_many(workers=2)`,
  순차 `predict`, 캐스케이드 없는 출력 모두 동일. `fallback_stats()` = (10, 8): 창 5개 × 2회, 빈 입력 창은 재실행 제외.
  `from_pretrained(fallback_repo=로컬 경로)` 배치 마스킹 동일. 한쪽만 지정, 0·음수·NaN·±무한대 마진은 `ValueError`.
- macOS 27.0.1 링커 문제로 로컬 확장 모듈은 `maturin develop --release -- -C link-arg=-Wl,-fixup_chains`로 빌드(해당 크레이트만
